# 领域包按部署生效，数据按领域包命名空间隔离

后端启动时由 `DOMAIN_PACK` 加载唯一一个领域包并全局生效；各领域数据按领域包名做命名空间隔离（Milvus collection 名前缀、MySQL 每个领域包使用独立 database、Neo4j 节点与关系的 `pack` 属性（Community 版只有一个库）、Redis key 前缀、MinIO 对象前缀）。切换领域 = 改配置并重启后端，数据互不影响。没有采用"租户绑定领域包、运行时切换"：那需要所有扩展点改为从请求上下文取领域包，并补齐 Milvus 前置过滤与 BM25 分租户索引，改动贯穿全链路且与创新点无关，还会威胁检索质量。

## Consequences

- 领域包格式与运行粒度无关，以后可升级为租户级而不改领域包。
- 注意 grid-qa 现有的租户隔离是后置过滤（先全局召回 topk 再按 `Document.tenant_id` 过滤），不能拿来做领域隔离。

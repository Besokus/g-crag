# 主评测使用 CRUD-RAG 中文新闻子集，电网领域包不作主评测

G-CRAG 的效果只有在"初次检索漏掉证据"时才能体现，而电网种子语料只有 8 篇、约 19KB，一次 topk 检索就能覆盖语料的一两成，几乎不会漏证据。因此主评测用 CRUD-RAG（IAAR-Shanghai，2023 年 7 月后的中文新闻）的单/双/三文档问答子集，加干扰新闻组成语料，构成通用领域包；电网领域包只用于演示和复盘。选择现成数据集而不是自己出题，是因为它自带标准答案和多文档结构，无需人工标注。

## Consequences

- 不可答题通过"删除其全部标准文档"构造，正确行为是拒答；同一事件的其他报道必须一并排除出语料（字面 + 语义过滤），否则答案会从旁路泄漏。原计划只删一篇，实测同题几篇片段内容高度重合（余弦 0.74~0.97），只删一篇答案仍在（09-27 修正）。
- 新闻发布于 2023 年，可能已进入 LLM 训练数据，需加闭卷基线并在报告中说明记忆泄漏程度。
- 规模可缩：标准配置为 150 题 + 约 3000 篇语料，时间紧时缩为 90 题 + 约 1000 篇。
- 格式已核实（09-27）：每题内联来源新闻（`news1..3`），但不带语料 ID；单文档题的来源新闻约 99% 不在官方检索语料 `80000_docs` 中，双/三文档题的 `news*` 是从拼接语料切出的片段（约 43% 跨越相邻无关文章）。因此以题目内联的 `news*` 片段本身作为标准文档，干扰文档另从 `80000_docs` 选取。构造规则见《设计文档》§16.13。
- CRUD-RAG 的双/三文档题本质是"多篇报道汇总"，不是严格的实体多跳链，图谱定位证据的收益可能小于理想多跳数据集；报告中按题型分别报告挽回率，如实说明。
- 数据集 README 标注 Apache-2.0（仓库内无 LICENSE 文件），新闻内容版权归原媒体；只用于课程评测，数据不提交到本仓库。

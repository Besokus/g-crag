# G-CRAG 改造方案文档

> 基于知识图谱与纠错机制的检索增强智能问答系统（G-CRAG）
> 版本 v2.0（2026-09-26），取代 v1.0 的"从零自建"方案。
> 术语以根目录 `CONTEXT.md` 为准；关键决策见 `docs/adr/0001`~`0007`。

---

## 1. 项目定位

### 1.1 一句话
把 grid-qa（电网运维 RAG，zhyese，CC BY-NC 4.0）改造成**通用的知识图谱问答系统**，并在其上实现本项目的创新：**让知识图谱驱动检索纠错（G-CRAG）**。

### 1.2 北极星
以"证明 G-CRAG 纠错确实有效"为第一目标。核心成果是对照实验与演示：同一问题下，原有纠错（不感知图谱）答错或幻觉，而 G-CRAG 通过图谱定位证据挽回答案，或在确实无依据时诚实拒答。系统以"能撑起对照演示"为标准，不追求产品级完善。

### 1.3 三个目标（一次改造同时服务）
1. **课程项目**：G-CRAG 创新 + 对照评测 + 演示。
2. **复盘 grid-qa**：吃透文档解析、OCR、混合检索、图谱、CRAG 全链路。
3. **沉淀通用 GraphRAG**：核心链路去领域化，领域知识以领域包形式可插拔。

### 1.4 本项目的贡献边界（报告须单列）
| 既有能力（grid-qa 原有，须署名） | 本项目新增贡献 |
|---|---|
| 混合检索（BM25 + 稠密 + RRF + rerank + MMR）、智能路由、查询增强 | **图谱定位证据**：沿图谱多跳遍历取回出处 chunk 作为纠错动作 |
| LLM 三元组抽取、实体归一化、Neo4j 存储 | **出处 chunk**：三元组关联到具体 chunk（批量抽取标序号 + 字符串校验） |
| CRAG 分级、LLM 改写重检索、拒答、证据补全 | **G-CRAG 纠错流程**：图谱优先、LLM 改写兜底、两轮上限 |
| 轨迹可视化、图谱可视化 | **实体链接策略链**（词典匹配 + 实体向量召回） |
| 评测脚本、golden 集 | **修复原有纠错的分级信号缺陷**（rerank 失败被误判为拒答/全部正确） |
| — | **领域包机制**（核心去领域化，电网包 + 通用包） |
| — | **基于 CRUD-RAG 的对照评测**（挽回率、拒答准确率、闭卷基线） |

> 不主张"把 CRAG 与 GraphRAG 结合"本身——grid-qa 中二者已并存，只是图谱不参与纠错（见 grid-qa `qa_service.py:256-288`）。

### 4.3 风险预案
- **G-CRAG 没有显著优于原有纠错**：如实报告，并按"未链接到实体 / 图谱无路径 / 路径有证据但 rerank 未采纳 / 采纳后仍答错"四类做失败归因。这本身就是有价值的分析；演示使用确有挽回效果的案例并说明其占比。

## 5. 评测方案

### 5.1 语料与题目（ADR 0007）
- **主评测**：CRUD-RAG 单/双/三文档问答各 30 题（本期采用缩量版），标准文档 + 干扰新闻组成语料，约 1000 篇。
- **标准文档**：直接用题目内联的 `news*` 片段（单文档题的来源新闻不在官方语料中，双/三文档题的片段不与原文对齐）；干扰文档从 `80000_docs` 选取，并排除与任一抽样事件相关的报道。
- **不可答题**：另抽 15 题（双 8、三 7），删除其全部标准文档（多文档题的几篇片段常是同一事件的不同报道，只删一篇答案仍在）；干扰文档已按事件（字面 + 语义）排除，答案不会从旁路泄漏。
- **电网领域包**：只做演示与复盘，不进主评测。

### 5.2 纠错模式（对照组）
| 模式 | 说明 |
|---|---|
| 无纠错 | 检索后直接生成 |
| 原有纠错 | grid-qa 原逻辑（信号缺陷已修复）：incorrect → LLM 改写重检索 → 拒答 |
| G-CRAG | 图谱定位证据优先 → LLM 改写兜底 → 拒答，最多两轮 |
| 闭卷基线 | 不检索，直接问 LLM |

### 5.3 指标
| 指标 | 定义 | 体现什么 |
|---|---|---|
| 准确率（按题型） | LLM 对照标准答案判定正确的比例，分单/双/三文档 | 整体效果，多文档题体现图谱价值 |
| **挽回率（按纠错动作）** | 初次分级为 ambiguous/incorrect 的题中，经该动作后可作答且答对的比例 | **创新点的直接证据** |
| 拒答准确率 | 不可答题的拒答率；可答题的误拒率 | 诚实性 |
| 代价 | 平均纠错轮次、端到端延迟、API 调用次数 | 效果与成本的权衡 |
| 闭卷准确率 | 闭卷基线的准确率 | 记忆泄漏程度 |

### 5.4 判定与可复现
- 答案判定：LLM 对照标准答案判对错，**人工抽查 20%**，报告判定一致率。
- rerank 结果录制回放：首跑写缓存，重跑读缓存，保证可复现并节省额度。
- 阈值（HIGH/LOW）在评测集的标定子集上扫描，报告标定过程。

### 5.5 附加实验（P1）
- **分级信号缺陷**：注入 rerank 故障，对比修复前后的拒答率与误判率。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 云端欠费/限流，建图或评测中断 | 录制回放；建图断点续跑；提前确认额度 |
| 通用语料建图耗时长 | 先用缩量版跑通全流程再扩量 |
| 图谱噪声大，图谱定位证据取回无关 chunk | 领域包 schema 约束；枢纽实体规则；出处校验 |
| 新闻已被 LLM 记住，基线虚高 | 闭卷基线量化并在报告中说明 |
| 裁剪时误删依赖导致链路断裂 | 每步跑测试；删除前用 codegraph 查引用 |
| 答辩被问到未改动的 grid-qa 模块 | M0 复盘；报告划清贡献边界 |
| 演示现场服务异常 | 健康状态显示、预热缓存、录屏备份 |

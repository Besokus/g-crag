# 父子分块方法论：检索精度与生成上下文的解耦

> 适用场景：知识库 RAG 中，文档切分粒度与喂给 LLM 的上下文粒度如何取舍。
> 本方法论从本项目（电网运维 RAG）落地实践中提炼，去设备相关细节，抽象为可迁移的设计原则与决策框架。

---

## 一、问题：朴素分块的三重困境

RAG 检索质量同时受两个相反方向的力拉扯：

| 力 | 要求 | 朴素单层分块的后果 |
|---|---|---|
| **检索精度** | 块要"小而纯"，embedding 语义集中，BM25 词频准确 | 块太大会稀释语义、引入噪声，召回不准 |
| **生成上下文** | 块要"大而全"，LLM 看到完整逻辑链 | 块太小则关键步骤/数值/表格被切断，答案断章取义 |

单层分块只能二选一，必然三重困境：

1. **切小了**：检索准，但一条操作规程被切成 3 块，LLM 只看到中间一块，丢前置条件或后续步骤。
2. **切大了**：上下文全，但一个 2000 字块里混了多个主题，embedding 被稀释，相关 query 召不中。
3. **结构被破坏**：表格、编号列表被字符切两半，数值脱离表头、步骤脱离编号。

## 二、核心思想：检索粒度 ≠ 生成粒度

> **底层逻辑：把"检索用什么块"和"生成用什么块"解耦——检索阶段要小而准，生成阶段要大而全，用一个稳定的纽带把两者连起来。**

这就是 Parent-Child Chunking（父子分块），检索侧叫 Small-to-Big（命中小块，召回大块）：

- **子块（child）**：入库向量库/BM25，承担检索精度。粒度小（本项目 500 字）。
- **父块（parent）**：同组子块拼接而成，承担生成上下文。粒度大（本项目 2000 字，约 4× 子块）。
- **纽带**：`parent_idx`（父块组号）——同组子块共享，命中小块后按它拼回父块。

一句话：**在子块上做匹配，在父块上做生成。**

## 三、设计原则

1. **解耦原则**：检索粒度与生成粒度独立可调，互不绑架。
2. **纽带稳定原则**：父子关系用一个确定性 ID（`parent_idx`）表达，入库时写入，检索时反查，不依赖位置推算。
3. **结构感知原则**：表格、标题、编号列表等结构单元是语义原子，不得被字符切分——整体成块。
4. **元数据透传原则**：定位元数据（页码、bbox、章节路径、表头）落在子块上，拼父块时保留，供引用溯源。
5. **父组去重原则**：同一父块被多个子块命中时，只返回一次父块，避免重复上下文。
6. **可退化原则**：提供总开关，关闭即退化为朴素单层分块，便于对比与回滚。

## 四、数据模型：parent_idx 作为纽带

一个 chunk 表既能存子块也能表达父子关系，关键是 `parent_idx`：

```
chunks 表关键字段：
  doc_id        文档外键
  chunk_idx     文档内顺序号
  content       块正文
  chunk_type    child | table | title        ← 结构类型
  parent_idx    父块组号（同组拼接=父块全文）  ← 纽带
  section       所属章节
  page_num/bbox 引用定位（PDF 高亮）
  table_header  表格类绑定的表头
```

**两个复合索引是性能命脉**：

- `(doc_id, parent_idx)` —— small-to-big 聚合按此查同组。
- `(doc_id, chunk_idx)` —— 引用回填、邻域召回按此序查。

> 没有 `(doc_id, parent_idx)` 索引，每次 small-to-big 都全表扫该文档所有 chunk，文档一大就慢。

## 五、切分策略：父→子两层 + 结构感知

切分是"建块"，分三步（本项目 `split_structured`）：

```
结构化解析 sections（text/table 段，带 page/bbox/header）
   │
   ├─ 表格段 ──► 整体成一个父组
   │             · chunk_type=table，绑 table_header
   │             · 绝不被字符切（数值不脱离表头）
   │
   └─ 正文段 ──► ① 父块：大窗口切（PARENT_SIZE，按段落/句末边界）
                 ② 每父块内切子块：小窗口（CHUNK_SIZE + overlap）
                 ③ 同父块子块共享 parent_idx（递增 group_id）
                 ④ 元数据(page/bbox/header)透传到每个子块
```

**三个细节决定切分质量**：

1. **句末边界切，不切半句**：超长段在目标长度附近找最近的句末符（`。！？；\n`）断开，而不是硬切字符。
2. **父块过短的兜底**：父块小于子块尺寸时，子块数=1，该子块 `parent_idx` 指向自身组——不破坏"命中→拼父块"的一致逻辑。
3. **章节启发式**：取首行短文本，匹配编号前缀（`第/一、/1.`）或领域关键词（`规程/步骤/措施`）作为 section，无标题则空串兜底。

## 六、检索策略：small-to-big 聚合

检索是"用块"，发生在召回/rerank/MMR **之后**、喂 LLM **之前**（本项目 `_expand_parents`，在 mixed_search 流水线第 6 步）：

```
rerank+MMR 后的命中池 pool（命中的是子块）
   │
   ▼ small-to-big
① 查 pool 涉及文档的全部 chunk（doc_id, chunk_idx, parent_idx, content）
② 建映射：chunk→parent、group→[同组子块列表]
③ 对每个命中块（按分降序）：
     · 取其 parent_idx → 拼 group 内所有子块 = 父块全文
     · 用父块文本替换命中块的 text（score/docId 等元信息保留）
     · 该 parent 已用过则跳过（去重）
   │
   ▼
喂给 LLM 的是完整父块上下文，不是孤立子块
```

**关键点**：

- 只发生在**召回之后**——在子块上做完了所有精确匹配/融合/重排，最后一步才膨胀为父块。否则父块进召回池会破坏 rerank 的精度信号。
- **去重**用 `used` set 按 `(doc_id, parent_idx)` 去重：多个子块命中同一父块，父块只返回一次。
- 元信息（docId/score/sources）保留命中块的，只替换 text——引用编号、来源归因不受影响。

## 七、参数决策框架

父子分块的效果高度依赖参数比例，决策框架如下：

| 参数 | 决策依据 | 本项目取值 |
|---|---|---|
| **子块 CHUNK_SIZE** | embedding 模型的最佳语义粒度（太小丢上下文，太大稀释）；通常 300–600 | 500 |
| **子块 OVERLAP** | 防边界信息丢失，通常 10%–20% of size | 80（16%） |
| **父块 PARENT_SIZE** | LLM 能消化的完整逻辑段；电网规程一段操作约 1500–2500 字 | 2000 |
| **父/子比例** | 经验值 3–5×：比例过小=退化单层，过大=父块噪声多 | 4× |
| **父块 OVERLAP** | 父块边界跨逻辑段时的容错 | 200 |

**调参原则**：

- 子块尺寸看 **embedding 效果**（用 golden 集测召回）。
- 父块尺寸看 **答案完整性**（看 faithfulness / 完整度评测）。
- 比例不是越大越好：父块过大让 LLM 上下文变长、成本上升、且引入不相关段落。
- 所有参数应**可热调**（运行时改），便于线上调参不重启。

## 八、工程实现要点

1. **索引先行**：`(doc_id, parent_idx)` 和 `(doc_id, chunk_idx)` 两个复合索引必须建，否则聚合和回填全表扫。
2. **元数据随子块走**：page_num/bbox/table_header 存在子块上，small-to-big 拼父块后仍可定位到具体页/框（引用高亮依赖此）。
3. **开关与退化**：总开关（`SMALL_TO_BIG_ENABLE`）默认开，关则原样返回命中块（朴素分块），便于 A/B 与回滚。
4. **独立 session**：若 small-to-big 在后台任务触发，用独立 DB session，不共享请求 session 生命周期。
5. **表格特殊处理**：表格 chunk 自身即父组（`parent_idx=自身组号`），不进子块切分流程，保证完整性。
6. **失败兜底**：查不到 parent（老数据/孤儿块）时原样返回，不抛错。

## 九、与相关策略的边界

父子分块解决"原文的精/全"，要和另外两个策略划清边界，避免概念混淆：

| 策略 | 解决什么 | 触发时机 | 与父子分块关系 |
|---|---|---|---|
| **父子分块（small-to-big）** | 命中子块 → 拼同组父块全文 | 召回后、喂 LLM 前（默认开） | 主策略 |
| **邻域扩展（neighbor expand）** | 证据不足时捞相邻 `chunk_idx ± N` 补上下文 | CRAG 判 ambiguous 时（默认关） | 补充：父子是"同组聚合"，邻域是"相邻序号"，正交 |
| **RAPTOR 层次摘要** | 原文 + 段落摘要 + 文档摘要多粒度融合 | 文档向量化后建摘要层（默认关） | 补充：父子是原文内精/全，RAPTOR 是原文/摘要的多粒度 |

> 一句话区分：父子分块在**原文内部**做精/全权衡；邻域扩展在**相邻位置**补证据；RAPTOR 在**语义层级**上加摘要层。三者可叠加，但默认只开父子分块。

## 十、踩坑与经验

1. **父块过短致子块=父块**：必须让 `parent_idx` 指自身组，保证"命中→拼父块"逻辑统一，不能因为父块短就跳过 group_id 分配。
2. **多子块命中同父未去重**：父块重复进 LLM 上下文，浪费 token 还可能干扰。必须按 `(doc_id, parent_idx)` 去重。
3. **表格被字符切**：表格里有换行/长文本，按段落切分会劈开表格。必须 `chunk_type=table` 整体成块 + 绑 `table_header`。
4. **切在半句上**：硬按字符切会把"主变油温应≤85℃"切成"主变油温应≤8"和"5℃"。必须句末边界切。
5. **small-to-big 放错流水线位置**：若在召回前就拼父块，rerank 的精度信号被父块噪声污染。必须在 rerank/MMR 之后。
6. **元数据丢失**：拼父块时若只取 text 丢 page/bbox，引用高亮失效。元数据必须随块保留。
7. **参数不可热调**：父子尺寸改一次重启一次服务，线上调参成本高。参数应进运行时热读缓存。

## 十一、演进路径

父子分块不是终点，可沿三个方向演进：

1. **动态父块**：当前父块尺寸固定。可按命中子块的"上下文需求"动态决定拼多大（简单事实拼小父块，操作步骤拼大父块）。
2. **语义父子（而非位置父子）**：当前 `parent_idx` 按切分顺序分组。可改为按语义聚类分组（同主题子块归一父），更贴合 LLM 需要的上下文边界。
3. **与 RAG 评估闭环**：把父子尺寸参数接入检索调参扫描（只建议模式），用 golden 集 + faithfulness 自动寻优，而非人工拍。

> **方法论一句话**：检索粒度与生成粒度解耦，用 `parent_idx` 做纽带，在子块上匹配、在父块上生成，结构单元不切碎，父组级去重，参数可热调——这是 RAG 知识库分块从"切了就用"到"精度上下文两全"的关键一跃。
